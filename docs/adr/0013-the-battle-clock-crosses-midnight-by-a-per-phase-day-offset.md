# The battle clock crosses midnight by a per-phase day offset

*Amended 2026-09-07: "`sort_date` is only ever compared, never arithmetic" is narrowed by ADR-0022 to allow one sum — the interval between two battles, which the library's chronology rail writes. No duration within a battle may be computed from it, and the reasoning below is unchanged (#129).*

ADR-0002 pinned every phase to a `"HH:MM"` instant on one battle date and said plainly that multi-day battles are not v1. The Nile runs from a 14:00 sighting on 1 August 1798 through the night to Villeneuve's escape at 11:00 on the 2nd, so its last two phases would have to carry times lower than the ones before them. We decided that a phase gains an optional **`day`**, a non-negative integer offset from the battle's first day, and that phases order on the pair (`day`, `t`); `t` keeps its `"HH:MM"` shape and its meaning, so every time in a file is still copied verbatim from the source that gives it. The battle's `date` becomes **`dates`**, one display string per day, which the caption band indexes by the current phase's `day`; the battle also gains **`sort_date`**, a machine-readable `{ year, month, day }` the library sorts on, with a negative year for BC.

Underneath this sits a definition ADR-0002 never wrote down: the battle clock is a **reading**, not an instant. The Nile's five primary witnesses disagree by up to 45 minutes on the same event and Cannae rests on a single sunrise fix, so there is no point on a global timeline to be had. The clock carries no timezone, is never UTC, and is never a JavaScript `Date`. That is what rules out the datetime options below, and it is why `sort_date` is only ever compared, never arithmetic.

## Considered options

- **A full date or ISO datetime per phase**. Self-contained, no offset to resolve. Rejected: it asserts an instant the sources cannot supply, and it invites a zone. ISO 8601 also cannot write 216 BC without its expanded-year extension, and `Date` is not to be trusted with proleptic ancient dates, so the shape that looks most standard is the one Cannae breaks first.
- **A clock running past 24:00** (`"29:05"` for 05:05 the next morning). One field, no new concept. Rejected: every quotation would be converted by hand on the way in and normalised again on the way out, so the file stops matching Berry's "five minutes past five in the morning" and the readout has to undo the encoding at exactly the moment the viewer most needs the clock to be true. Ships' logs of the period already run a nautical day beginning at noon; a second offset clock on top of that is a trap.
- **Two battle files**, `nile-evening.json` and `nile-morning.json`. Needs no schema change at all. Rejected: the pause across midnight becomes a page load, and one battle stops being one file, which is the assumption the library (ADR-0011) is built on.
- **Deriving day 2's date string by arithmetic** on `sort_date` rather than authoring it. Rejected: it needs a formatter that renders words the author should be free to choose, and a calendar the project has no reason to own. Keeping `sort_date` arithmetic-free is what lets it use ordinary historical year numbering.
- **`end` as an object** `{ day, t }`, with phases matching. Reads better in isolation; rejected because it rewrites every phase in every existing file to express something two optional fields already say.
- **A `night` flag on the phase**, so a view could know the Nile is dark. Rejected: with a day offset the file already says it is 23:00, sunset is in the caption in Berry's own words, and a flag would be a second source of truth that quietly pressures the viewer's choice of view, which the design-language decision (issue #58) deliberately left to the viewer.

## Consequences

- **`day` is optional and defaults to 0**, so every file written against v1 stays valid unchanged; Trafalgar needs no edit. The first phase must be on day 0, phases strictly increase on (`day`, `t`), and no `day` may point past the end of `dates` or leave a trailing entry unused.
- **`end` gains `end_day`**, optional, defaulting to **the last phase's `day`** rather than to 0, because "later than the last phase" is only meaningful on the same day. The Nile ends at 14:00 with `end_day: 1`, the thanksgiving on Vanguard's quarterdeck; the 3 August coda is caption matter, not a third day.
- **`date` becomes `dates`**, a non-empty ordered list of display strings, one per day. Trafalgar is `["21 October 1805"]`. The caption band shows `dates[day]` beneath the clock, so the date advances with the battle; the library shows `dates[0]`.
- **The scrubber readout stays a bare `"HH:MM"`.** The caption band directly above already carries the date and updates as the viewer scrubs, and the readout is the wrong place to spend width on a phone.
- **The clock becomes a running total from midnight of the first day.** Day 1 at 05:05 is 104,700 seconds, so it stays monotonic and the timeline core keeps comparing plain numbers: tweening, intervals and scrubbing are untouched, and only `formatBattleTime` learns to take a remainder. This replaces "seconds since midnight on the battle's date" wherever the code says it.
- **`sort_date` restates `dates[0]` in machine form and nothing can check the two agree**, since no validator can parse "216 BC" out of prose. This is an accepted cost, recorded here so it is not mistaken for an oversight: the alternatives were parsing the display string or generating it, and both are worse. Its year uses ordinary historical numbering, so Cannae is `-216`, not the astronomical `-215`; ordering still holds because there is no year zero to fall into and nothing is ever added to it.
- **Wind and the map are untouched by the Nile's night.** No source records a shift, so `fresh` before dark and `moderate` after is an authoring choice inside ADR-0008's existing enum, and one map file is still one moment (ADR-0012) for a bay that does not change overnight.
- **ADR-0002 stands amended, not superseded**: its snapshot-tween model, its step semantics and its strictly-increasing rule all hold, with the ordering key widened from `t` to (`day`, `t`) and its "multi-day battles are not v1" note settled for v2.
