# A battle is a page at its own path, and its card is its own still

ADR-0011 gave the site its front door and addressed a battle by `?battle=<name>`. It considered pretty paths and rejected them for v0.2 — GitHub Pages serves static files, so a path needs either an `index.html` per battle or the `404.html` routing trick — and then wrote the escape hatch in the same breath: *"Per-battle copies of the page can be emitted later without changing what the app reads."* [#150](https://github.com/NullCoderException/marchpast/issues/150) came back for it.

**The build emits a page per battle at `/<name>/`, and that page's social card is the battle's own still.** `marchpast.com/trafalgar/` is a copy of the same document over the same bundle, with its own title, description, canonical and card. `?battle=` stays readable and is never emitted again. Decided on [#150](https://github.com/NullCoderException/marchpast/issues/150).

The question reads as a card question and is not one. `index.html` today carries **no `og:` tags and no meta description at all**, so every URL this site has — the library and all four battles — unfurls as a bare title in every client that previews a link. [#135](https://github.com/NullCoderException/marchpast/issues/135) chose S2 to fix that, a single designed plate on parchment, and cut S1, a real build-time still, on semantics rather than machinery: **one card is site-wide, so a still pins one battle to every link the site has**, and every share of every page would unfurl as Trafalgar. A crawler never runs the app and a static host cannot vary a `<meta>` from a query string, so the only way a battle's link can unfurl as that battle is for the battle to have a document of its own. The card is downstream of the URL.

What changed since ADR-0011 is that the bill is already paid. **ADR-0025 parameterised the still** over battle, map, phase, view, level, size, DPR and crop, and named this ticket while doing it: the card is that same call at 1200 × 630 with the caption band kept, two crops of one render. And **the base path is gone** — since [#136](https://github.com/NullCoderException/marchpast/issues/136) the site serves from the root of its own domain, `paths.ts` hangs every data URL off a bare `BASE_URL`, and Vite emits absolute asset URLs — so a document nested at `/trafalgar/` fetches `/data/…` and `/assets/…` unchanged. Depth costs nothing. What remains is one `transformIndexHtml` in the build and a second file per battle.

The path is the **bare name at the root**. The site is only battles: the library is the root and the battles are its contents, so there is no second kind of thing a prefix would disambiguate from, and a prefix that disambiguates nothing is length in the one place length is most expensive. ADR-0011's own imagined shape, when it rejected pretty paths, was `/sandtable/trafalgar/` — the bare name under the base — and the domain has since deleted the base.

The picture is the **still alone**, with its caption band and no brand panel. #135 cut S1 for two reasons and only one of them is repaired here: the semantic objection dies with the per-battle page, but *"the panel also eats a third of the plate it is advertising"* gets worse now that the plate is the whole point. It is also redundant twice over. Every preview client prints the site name and the domain as text beside the image, so a panel spends a third of the picture reproducing the chrome; and `drawCaption.ts` states the band's purpose in its own header — **"Part of the picture, so a screenshot stands alone"** — so the frame already carries the battle's title, its date, the clock, the phase label and one sentence of what is happening, in the app's own materials. A panel would stack a second strip under the first.

## Considered options

- **The query parameter alone, S2 standing as the site's only card.** Rejected. It is the status quo and it is coherent, but it settles for every link to every battle looking identical, and a per-battle card is the single largest difference a link can make. It also forfeits a real `<title>` and description per battle for search, which is the same argument the meta description won in #135. The reason to have refused it was cost, and ADR-0025 removed the cost.
- **A meta-only shadow page**, `/<name>/index.html` carrying the tags and bouncing to `/?battle=<name>`. Rejected. It preserves ADR-0011 whole and buys the card, but it trades away the entire user-facing half — a real URL, a real address bar, an indexable page — for a flash and a double navigation, and the URL a reader copies is not the one they landed on.
- **`/battles/<name>/` or `/battle/<name>/`.** Rejected on the argument above: the prefix is permanently safe and permanently pointless. It is the reserve if the root namespace ever has to hold something battles cannot be.
- **The `404.html` routing trick**, which ADR-0011 rejected for answering a 404 status to crawlers and link previews. Still rejected, and worth separating from the `404.html` this ADR *does* add: there the status was a lie told about a real page, here it is the truth about a page that is genuinely not there.
- **Still plus the S1 parchment panel** across the foot, as #150's own body proposed. Rejected on the argument above.
- **A card composed for sharing** — the battle's title and date set into the picture over the still. Rejected: that is what the caption band is, and drawing it twice in two type systems is worse than drawing it once in the app's.
- **Retiring `?battle=` outright.** Rejected, and it is nearly free — the query form is one day old on this domain — but the app already parses a query string for `?fixture=`, so keeping a read-only branch costs one line and breaks nothing that was ever shared.
- **The page declaring its battle in a `<meta>` the app reads**, so the URL shape lives only in the build. Rejected on dev parity: Vite's SPA fallback serves the untransformed `index.html` for an unknown path, so `/trafalgar/` in dev would carry no such marker and would show the **library**. Parsing the path is the only rule that works when nothing has transformed the document, and `serve-data.ts` exists precisely to stop dev and the build disagreeing about a route.
- **`cardUrl(name)` in `paths.ts`**, a fifth sibling to `battleUrl`, `mapUrl`, `indexUrl` and `stillUrl`. Rejected: that module's own docstring says it turns a name into *"the URL the app fetches"*, and nothing in `src/` will ever fetch a card — the build writes it and a crawler reads it. It would be the first dead entry in the file.
- **`data/stills/<name>-card.png`**, the card beside the still. Rejected: keeping `dist/data/stills/` as exactly the set of pictures the library shows is what makes a stray file obvious.
- **A `sitemap.xml` and a `robots.txt`.** Rejected: seven pages, every one of them linked from the root a crawler starts at, and a sitemap would be a second list of battles free to drift from the first — the argument ADR-0011 used to refuse a hand-written index.

## Consequences

- **ADR-0011's URL clause is amended**: a battle is addressed by path, and the query form survives as a legacy reading. Everything else that ADR decided stands, the library included — it is still the front door, still built from the battle files, still chronological.
- **`battleName.ts` gains `battlePath(name)`**, and it is the one place the shape lives: the library's links, the Picker and the build all call it. `battleQuery(name)` stays beside it as the legacy form, read but never emitted.
- **The app reads `location.pathname`**, taking precedence over the query, and `replaceState`s to `/<name>/` when it arrives by the old form, so the wrong URL stops propagating rather than merely being tolerated. There is no server to redirect with: Pages serves what the build emits.
- **`/?battle=<name>` is served by the library's document**, so a crawler fetching that form still gets the library's card and the library's title. This is unfixable on a static host and is accepted because nothing emits that URL any more.
- **`?fixture=` is untouched.** A fixture is not in the library and is never shared, so it gets no page (ADR-0011).
- **The head of a battle page** carries `<title>` `<Battle> — Marchpast`, matching what `main.ts` already sets at runtime; `description` and `og:description` from the battle's **`summary`** verbatim, a field whose whole definition is what a battle says of itself where it is named but not played; a **bare `og:title`** with no site suffix, because every client prints `og:site_name` or the domain on its own line and the suffix would set the name twice inside a box three lines tall; `og:site_name`, `og:type`, an absolute `og:url`, `og:image` with its width, height and **a real alt**; `twitter:card: summary_large_image`; and `<link rel="canonical">`.
- **The card's alt is written, and the thumbnail's stays empty.** Not a contradiction of ADR-0025 but its mirror: a thumbnail is `alt=""` because the entry beside it is already named by title, date and summary, while a shared card may reach a reader with no adjacent text at all. The build has the material in hand as it renders — the battle's title and the still phase's clock and label.
- **The card is `data/cards/<name>.png`**, written by `vite/stills.ts` and absent from `paths.ts`. A card that fails to render **fails the build**, on ADR-0025's own terms.
- **The site's canonical origin becomes a constant in the build**, hardcoded: `og:image` and `og:url` must be absolute, and #136 established `marchpast.com` as the one canonical origin with `.app` and `.org` 301ing to it, so there is nothing to vary. A local build emitting absolute URLs at the live site is correct for the only consumer there is.
- **The build emits `404.html`** in the brand's materials — parchment, the mark, "No such battle", a link to the library. It is the first page the site has that is not the app: a plain document, no bundle.
- **The load-error notice loses most of its ground.** [#130](https://github.com/NullCoderException/marchpast/issues/130) moved it into the DOM so a failed load is not silent to a screen reader; in production an unknown name now never reaches the app at all, because `404.html` answers first. What is left to it is a network failure and the legacy query form — narrower, and not redundant.
- **Battle names and top-level routes share one namespace.** `data` and `assets` are reserved, and so is anything else the build ever emits at the root. The validator already walks every battle file, so one rule turns a live collision into a build failure.
- **The still's view is simply the default view.** ADR-0025 left a conditional — *"if a battle may suggest a view, its still follows"* — and #153 closed it in the negative (ADR-0014, amended): no battle names a view, so the thumbnail and the card are both drawn in the default, and there is nothing here to follow.
- **The library keeps S2** as its own card and gains a canonical to the root. One designed plate for the site, a still for each battle.
- **[#141](https://github.com/NullCoderException/marchpast/issues/141) carries the URL change into the v0.3 issues**, and the `404.html` with it — a page to draw in a language #135 already settled, which is build work rather than a decision left open. [#151](https://github.com/NullCoderException/marchpast/issues/151) is unaffected beyond the target of the link it draws.
- **Glossary**: **Battle page** and **Social card** added, **Library** amended to name the per-battle page, **Thumbnail**'s avoid-list extended now that *card* means something exact.
