# Positions are real latitude/longitude, not abstract map units

*Amended 2026-09-06: the formation vocabulary is three words, not two (`mass` added by ADR-0016), and the schema now carries one length-bearing field outside the battle file, a contour's elevation in metres in the map file (ADR-0012). Everything else here stands.*

*Amended 2026-09-07: the "positions carry no uncertainty field" clause below is confirmed at the hardest case the library holds — the Little Bighorn, where one battalion’s five phases are read off the dead and the cartridge cases — by [ADR-0027](0027-conjecture-is-notes-matter-and-a-battle-authors-one-reading.md), which rejects a per-unit `conjectural` flag and a `basis` enum and sharpens the glossary’s **Position** to the author’s reading of where a unit’s centre was (#133).*

*Amended 2026-09-07: longitude runs continuously east from the extent's western edge rather than folded into `-180..180`, so a battle crossing the antimeridian writes an `east` past 180 and positions to match (#143). The box, the fit and the letterbox are unchanged, and `west < east` still holds of every file. Everything else here stands.*

Battle files could have used per-battle abstract units (a 0..1000 box with its own "north"), which is simpler to sketch, or real WGS84 latitude/longitude. We chose lat/lon in decimal degrees from day one: the sources already speak in bearings and distances from named places (Cape Trafalgar, Cadiz), heading and wind need a real north regardless, and real coordinates make the coastline, later basemap tiles, and cross-checks against logged positions free. A battle with a disputed site still gets a best-guess lat/lon, so this does not foreclose land battles.

## Consequences

- Each battle declares an **extent**: one lat/lon bounding box, fixed for the whole playback. The renderer fits it to the canvas preserving aspect ratio and letterboxes the rest. Per-phase extents (a moving camera) are not in v1.
- **Longitude is continuous, not folded** (2026-09-07). The extent's `west` is spelled canonically in `-180..180` and its `east` runs east of it, no further than `west + 360`; every longitude in the file is then read in that frame. A battle crossing the **antimeridian** therefore has an `east` past 180 — Midway is `west: 173, east: 187.25` — and writes its positions the same way, so Mikuma's grave at 173.5 E is `173.5` and Yorktown's at 176.57 W is `183.43`. The cost is a second legal spelling for every place on earth. No viewer ever sees it: a longitude is never displayed, only projected. What it buys is that the projection and the tween cross the line with no special case at all — both are already linear in longitude — and that `west < east` stays true of every file instead of becoming conditional. A box that wraps when `west > east` was rejected for spending that invariant and for putting an unwrapping branch into the two purest functions in the codebase, one of which only a single battle in seven would exercise.
- The projection is a renderer implementation detail, never a schema field. The renderer uses Web Mercator so that future basemap tiles line up without reprojection; at battle scale it is visually identical to equirectangular.
- **Heading** is numeric degrees true. No compass-point strings, no radians, no dual representation.
- Schema v1 has no length fields. The only unit-bearing field is a per-battle scale-bar display unit (nautical miles or kilometres). If a later decision needs a length, it is stored in metres and the display unit converts.
- A unit's **position** is a single centre point plus a heading. Formation shape is a label the renderer styles, not geometry (the v1 vocabulary, `column` and `line`, is fixed by ADR-0009). Positions carry no uncertainty field; source disagreements are a caption and references matter (ADR-0006).
