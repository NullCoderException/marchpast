# The renderer draws views, and the chart plate is the default

*Amended 2026-09-06: the control that switches views is a `<select>` beside the speed multiplier, decided on #47 with no ADR; the Level chooser sits beside it (ADR-0017); the hovered or pinned unit of the unit card joins the view and the level as per-frame viewer state passed to `render` (#60).*

*Superseded in part 2026-09-07 by **ADR-0021**, which admits a second aesthetic: a view is no longer a palette, pens and a glyph and nothing else, the map, furniture, caption and label passes no longer never change, the label is a view's to draw, and a fourth view is no longer only a value in the views file. What still stands is where the view lives — a per-frame argument to `render`, never on the `Picture` and never `createRenderer` configuration — the glyph's two halves and the mark-before-body order, the scratch canvas, and a glyph never learning a compass bearing.*

ADR-0009 decided that the renderer draws an engraved chart plate, and the v0.1 renderer took it literally: the parchment, the ink, the letterbox and the side palette were module constants that every drawing pass imported by name. The design-language decision (issue #58) settled that there is one engraved system and that a **view** is a named treatment built from it, never a second aesthetic, and named three for v0.2: the **Chart plate** (default), the **Night plate** (the plate inverted, for the Nile) and **Atlas** (units as blocks, strength as the filled fraction, engaged as a hatched zone, thicker arrows). So the renderer draws views, and the chart plate is one of them.

A view is a **palette**, a set of **pens** and a **glyph**, and nothing else. Every other drawing pass is shared and takes its colours off the palette. The seam was cut in the real renderer over the real Trafalgar data on [prototype/second-view](https://github.com/NullCoderException/marchpast/tree/prototype/second-view), which is what settled the two shapes prose could not: that the Night plate needs no code at all, and that the glyph has to be two passes rather than one.

## Considered options

- **A palette and nothing else** — a view is a table of colours. Enough for the Night plate, which is why it was tempting. Rejected: Atlas draws a unit as a solid block with a filled fraction, and no colour table expresses that.
- **A renderer per view.** Each view owns its whole pipeline, free to diverge. Rejected: it makes three copies of the projection, the furniture layout and the caption band — exactly the things #58 fixed across views so they could not drift — and the third copy is where they drift.
- **A flag read inside each pass** (`if (view === "atlas")`). The smallest diff. Rejected: the branch reappears in every pass, each new view multiplies it, and the legend would have to know Atlas exists in order to draw Atlas's sample.
- **Every pass replaceable**, a full table of overridable passes. Rejected: nine extension points of which the three decided views exercise one. Drawn out over the same scene, the map, furniture, caption and label passes came out identical for all three views; an extension point no view uses rots before the view that needs it arrives.
- **The view on the `Picture`.** Rejected: the picture is what the timeline computed for an instant and is the same for every viewer; the view is what one viewer chose. Putting it there would make two viewers of the same instant hold different pictures.
- **The view as `createRenderer` configuration.** Rejected: the viewer switches at any instant, and the renderer holds nothing but the canvas and its context, so a per-frame argument is honest and rebuilding the renderer on a switch is not.
- **The palette published as CSS custom properties**, so the player's controls go dark with the Night plate. Rejected for v0.2; see the consequence below.

## Consequences

- **A view is a palette, a set of pens and a glyph.** The **palette** carries the ink, the paper (the sea and the caption band alike), the land, the letterbox, the legend's panel, the coastline's stroke, the sea's stipple (absent means flat paper), and the side inks. The **pens** carry the three motion styles' weights, dashes and heads, but never their colours, which come from the palette and the side inks, so a view never restates a colour it has already declared. The **glyph** is how a unit is drawn. Nothing a view owns comes from data: no battle file names one.
- **The Night plate is a palette and nothing else** — the same passes, the same glyph and the same pens as the Chart plate. That is the seam's proof: an inverted view costs one value table and no code.
- **Atlas replaces the glyph, re-tunes the pens and turns the stipple off.** Its pens thicken by no single factor (track 1.6, intent 2.4, detachment 3.2 with a head of 14 against the plate's 1.2, 1.2 and 1.8/11), which is why pens are three explicit styles rather than a multiplier.
- **A glyph has two entry points, `mark` then `body`, and the units pass runs every unit's mark before any unit's body.** An engaged mark is wider than the unit it belongs to, and the plate's smoke is opaque where it is drawn; per unit, one unit's smoke covers the next unit's ships. Trafalgar at 13:30 is three overlapping units and Cannae is worse. This is the concrete shape of "the engaged mark is a pass a view replaces": it is inside the glyph, but as its own half.
- **The engaged cloud is composited on a scratch canvas.** The union of its puffs is filled in ink and the same union, eroded by the line width, is punched back out with `destination-out`, then the result is stamped onto the plate — because punching on the plate itself takes the sea with it. The cloud's interior is therefore genuinely empty rather than filled with paper, so at Cannae a fighting wing sits on the ground instead of in a hole in it. The cost is one scratch canvas, shared by every cloud on every frame.
- **A glyph never learns a compass bearing.** It is drawn at the origin heading up, and the wind reaches it as a single angle clockwise from the unit's own heading, absent when the phase has no wind, the wind is calm, or the caller is the legend. So #58's lee-flank rule — the across-hull component never below about half, the along-hull component damped — lives inside the glyph, and the projection stays out of it.
- **The label pass is shared, and the label is not a view's to replace.** #58's "a view owns the label style" narrows to its inks: the two-line anatomy, the placement rule and the collapse order (issue #39) are one implementation for every view. The one thing the label needs from a glyph is **how far it reaches across its long axis**, so a block's label clears its hatching and a column's clears its ticks. A fourth view that genuinely needs different label anatomy cuts that seam then, with a case to design against.
- **The map, furniture and caption passes never change.** The projection and north-up, the furniture set and which corner each piece sits in, and the caption band's anatomy are fixed across views. They take their colours from the palette, which is how the Night plate gets a dark shore and a dark band for nothing, and how the legend draws Atlas's blocks without knowing Atlas exists: it samples the view's own glyph at a smaller scale, and the glyph is told the scale so it can leave off detail too fine to read.
- **The view is a fourth argument to `render`, and a view id in player state** beside the speed multiplier: viewer-chosen, never authored, and gone on reload like the rest of it. The renderer stays stateless but for its canvas.
- **The view stops at the canvas edge.** The player's controls stay in the plate's language whatever view is picked, and no palette value reaches CSS. A dark plate under a light control bar is the accepted cost. The reasons: a view is a treatment of the *picture*, so a screenshot of the canvas is still the whole view; and making the controls follow would oblige every future view to supply control-legible values as well as plate values. Issue #47 decides the control that switches views; this decision only says that control does not itself change colour.
- **Adding a fourth view is a value in the views file**, plus one glyph module if — and only if — it draws a unit differently.
- **Atlas's heading nose is a barb, not a taper of the whole block.** A full-width nose turns the block into an arrow, which puts it in competition with the detachment move, itself a solid arrow in the side ink. The block keeps a rectangular silhouette at the cost of some heading legibility at small sizes.
- **The no-battle notice takes the default view's palette.** It is painted while the battle is still loading, before there is player state to hold a view, and it is the only place outside the drawing passes that reaches for one.
- **ADR-0009 stands superseded in one clause only.** Everything it decided still holds, as the Chart plate and as the system every view is built from: the glyph's meaning (formation is arrangement, state is one of four words, strength is the shown fraction), the three motion styles and the requirement that they stay tellable apart when they overlap, the full-width caption band, the furniture set, the fixed side palette by roster order, IM Fell English loaded before the first frame, landscape extents, and rendering checked by eye. What no longer holds is that the plate is the only treatment. Its alpha-wash smoke is also gone, replaced by #58's Billow.
